`Nautilus.Roots.bisection`, `newton` and `brent` now return NaN as soon as a NaN reaches them instead of iterating on it: a NaN `tol`, a NaN bracket endpoint or starting point, or a NaN from `f` (or from `df`) at any point they evaluate. Every guard in all three functions is a comparison, and every comparison against NaN is false, so a NaN residual previously fell through the tolerance exits, the `f(lo) * f(hi) > 0` sign-product check and `bisection`'s `same_sign` bracket update alike. The two consequences were different and both wrong. `bisection` collapsed its bracket onto `lo` and returned a plausible finite number -- `-0.49999997` for a residual that is NaN everywhere on `[-0.5, 2.0]`, and the same for a residual that is finite with a genuine sign change at the endpoints and NaN inside -- which is a silent wrong answer from a `stable` export, not the NaN the book promised. `brent` and `newton` did reach the documented NaN, but only by consuming the whole `max_iters` budget first, and that recursion depth aborts the process under `chelis eval --file`: measured at the `=0.18.12` pin, `brent` on a nowhere-finite residual survives `max_iters = 40` and aborts at `50` with `fatal runtime error: stack overflow, aborting`, while the identical call returns NaN under `chelis test`, whose worker has more usable stack. That threshold is a property of this workstation and will differ on a runner; the lane difference is structural and the upstream half is `chelis#2471`. An infinite residual is deliberately still accepted: `-inf` and `+inf` carry a sign, so a bracket whose endpoint residual is infinite is a valid bracket, and two new tests pin that `bisection` and `brent` still converge to `1.0` on one -- the reason the guard tests `neq(x, x)` rather than reusing `Nautilus.Optim`'s non-finite idiom, which would have rejected those brackets. A NaN also reaches `bisection` without any help from `f`: the midpoint of the unbounded bracket `(-inf, +inf)` is NaN, and `f(x) = if x < 0 then -1 else 1` is finite there, so the residual guard cannot see it; `bisection_rec` therefore rejects a NaN midpoint as well, which `brent`'s trial-point guard already covered. Ten tests pin the NaN cases; all ten are red against the previous `src/roots.ch`, two as assertion failures and eight as stack-overflow aborts, and the three control tests stay green on it. Signatures are unchanged, so the `stable` freeze in `SKILL.md` §6 holds and no call site breaks. Addresses nautilus#114.
