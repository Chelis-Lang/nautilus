`Nautilus.Distributions.gamma_cdf` and `gamma_sf` validated neither parameter, so a zero or negative `scale` produced a non-finite standardised argument `x / scale`, the continued fraction never satisfied its convergence test, and the recursion spent its whole 200-iteration budget. `chelis eval --file` evaluates on the `main` thread, does no tail-call elimination, and overflows its stack at about 135 frames of a body that size, so the process died with `fatal runtime error: stack overflow` and exit 134 and no diagnostic a Chelis caller could catch; `chi_squared_cdf`, `chi_squared_sf`, `Nautilus.Testing.chi_squared_p_value`, `gamma_inv_cdf` and `poisson_cdf` all inherited it. The same abort was reachable from inputs that are not degenerate at all: `gamma_cdf(2000.0, 2000.0, 1.0)` needs 187 series terms and `chi_squared_cdf(4000.0, 4000.0)` reaches it through `df / 2`, and a chi-squared test on 4000 degrees of freedom is ordinary. Both halves are repaired. `gamma_cdf` and `gamma_sf` now carry the guards `gamma_pdf`, `gamma_inv_cdf` and `weibull_cdf` already use in this module -- NaN for a non-positive `shape` or `scale` and for a NaN argument, the limits 1.0 and 0.0 at x = +inf, 0.0 and 1.0 at x <= 0 -- which agree with SciPy's `gamma` and `chi2` on every enumerated row, and they read the standardised argument so a finite `x` whose `x / scale` overflows lands on the same answer. Both incomplete-gamma recursions now spend their 200-iteration budget in chunks of sixteen through an outer driver, costing about 30 frames instead of 200. The arithmetic inside the guards is untouched: two independent red-team passes compared the shipped functions against a verbatim transcription of the flat recursion and found zero bit differences (that comparison bounds the chunking, not the guards, since both recursions sit inside them) -- 372 converging points in the first, and 700 points in the second covering both branches, every residue mod 16 of the iteration count in each branch, exact f32 straddles of the `shape + 1` boundary, convergence on the first, last and last-allowed step of a chunk, and 59 budget-exhaustion points the first pass could not reach. Neither pass found an input that exercises the two `1e-30` Lentz clamps, so those remain compared as code rather than as a taken branch; the smallest magnitude either reviewer observed there was about 3.6. A non-converged budget still returns the partial sum, so values change exactly where the new guards fire -- three input classes, not a list of cases, and stating it as a count was wrong twice before it was stated as a rule. Every call to `gamma_cdf` or `gamma_sf` with `shape <= 0` or `scale <= 0` now returns `NaN` whatever `x` is, while a caller with its own earlier domain guard (`gamma_inv_cdf` at `q <= 0` or `q >= 1`, `poisson_cdf` at `k < 0`) keeps the answer that guard already gave, unchanged by this PR: `gamma_cdf(1.0, 0.0, 1.0)` was `1.0`, `gamma_cdf(1.0, 2.0, -1.0)` was `0.0`, `chi_squared_p_value(5.0, 0.0)` was `0.0`, and `chi_squared_cdf(5.0, -1.0)` was a plausible-looking `0.99605733` that a consumer could have been using -- all `NaN` now, all `nan` in SciPy, and consistent with `student_t_cdf`'s existing `df <= 0` rule. Every call whose standardised argument `x / scale` is `+inf` now returns the limit instead of `NaN`: `gamma_cdf(+inf, 2.0, 1.0)` and the overflowing finite case `gamma_cdf(1e30, 2.0, 1e-30)` were `NaN` and are `1.0`, their survival functions `0.0`, which is the half of nautilus#140 the parameter guards do not cover. And a NaN standardised argument returns `NaN` where some shapes previously trapped in `cast_trunc`. Outside those three classes nothing moves. An earlier revision of this change also converted a non-converged budget to `NaN`, on the reasoning that every budget-exhausting input had aborted anyway; that reasoning was false outside the `chelis eval` lane, and the rule discarded a 1.5e-4-accurate answer at `shape = 2339` while keeping the 1.6e-3 one at 2338, so it was removed. The series' accuracy limit at large `shape` is long-standing and is now documented rather than changed: relative error at `x = shape` is 1.9e-6 at `shape = 100`, 2.8e-4 at 1000, 6.5e-4 at 2000, 1.6e-3 at 2338 and 16% at 20000, with nothing signalling the transition from a converged value to an abandoned one -- which at `x = shape` happens at `shape = 2339`, and at the branch's worst `x` just below `shape + 1` at `shape = 2311`. The first partial sum is ten times more accurate than the last converged value (1.5e-4 at 2339 against 1.6e-3 at 2338), which is why converting a non-converged result to `NaN` would lose accuracy rather than protect anyone. Six of the twelve regression tests pass against the unpatched module and are value pins rather than detectors of the abort, because `chelis test` runs each file on a `chelis-test-worker` thread holding about 500 frames of the same shape; the detector is `example_gamma_cdf_degenerate_arguments`, which encodes five of the cases as decimal digits and prints `11111.0` under the CI step that evaluates `src/example*.ch`, against exit 134 before this change. `betacf_rec` in the same module carries the same budget with a fatter body and is **not** chunked, so `beta_cdf`, `f_cdf` and `binomial_cdf` can still abort the eval lane; that surface is recorded as uncovered in `docs/UPSTREAM_BUGS.md` rather than claimed fixed. The eval-lane limitation itself is upstream `chelis#2471`. Addresses nautilus#140.
