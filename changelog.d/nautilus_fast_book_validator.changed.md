`scripts/validate_book_examples.py` runs in about 8 seconds instead of about 130 on a local 8-core machine, with every check kept. A `chelis` call loads every module in its package, which cost about 2.7 seconds per call; each call now runs in a private package holding the repository's `reef.toml` and `reef.lock` and only the `src/` modules the example imports, directly or transitively, which costs about 0.3 seconds. Each page's complete modules and captured fragments are evaluated as one program, with marker bindings so every output block is matched only against its own fragment's output. A fragment falls back to being checked alone, exactly as before, when the page program fails, does not show its output, or would lend it a name that only a later block defines. Jobs run in parallel on `os.cpu_count()` workers (`BOOK_VALIDATOR_JOBS` overrides). The floors (9 modules, 35 output examples), the pairing rules, the empty and unpaired output failures and the unique temporary names are unchanged, and the validator no longer writes into the repository's `src/` at all. Checked by planting a wrong digit in an output block, a type error in a complete module, and a fragment that uses a name only a later block defines: each fails and names its page and line.
