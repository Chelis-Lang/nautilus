`Nautilus.Optim.newton_minimize_1d` now reports NaN when `ddf(x)` is not finite, where before an infinite second derivative produced a plain float that no curvature check had verified. The `0.01` floor and the `<= 0` sign test already rejected a NaN, but an infinity is not NaN and reaches a point as a certified minimum by two separate paths, both measured at the `=0.18.12` pin on `(x-3)^2` with the correct first derivative. On the stepping path, `step = g / +-inf` is `0`, so `x_next == x` and the `eq(x_next, x)` early return hands back the starting point from a branch the iterate entered *because* the gradient test had failed: a `ddf` that is `+inf` everywhere, and one that is `-inf` everywhere, at `x0 = 5.0`, `tol = 1e-6` both returned `5.0`, unchanged at `max_iters = 10000`. On the convergence path the curvature check does run and accepts, because `+inf` is literally positive and above `0.01`: the same `+inf` curvature at `x0 = 3.0` returned `3.0` as verified, and with `tol = 10.0` loose enough to accept `x0 = 5.0` as converged it returned `5.0`. The two paths are independent -- reverting either guard alone leaves exactly its own cases wrong and the other's correct -- so both call sites were changed, and the first path is the one nautilus#117 documents. The new predicate is `x - x != 0`, which is the non-finite test and deliberately not this module's `neq(x, x)`: NaN-only is what the previous guard already was. That is the opposite of the choice `Nautilus.Roots` made in #115, where `-inf` and `+inf` carry a sign and an infinite endpoint residual is a valid bracket; a curvature of `+-inf` is a degenerate second derivative with no usable step, so the sign is not load-bearing here. Four tests were added. Two are red against `origin/main` and each pins one call site in isolation: the start-point test fails when only the stepping guard is reverted, the certified-point test fails when only the convergence guard is reverted. The other two are green against `origin/main` by design and exist as controls, not as evidence for this change -- one pins that a finite curvature still converges at `tol = 1e-6` and `tol = 0.0` and that the `0.01` and `1e-30` thresholds still reject on their own, and one pins that a *finite* negative curvature at a stationary point is rejected by the sign test, which this change neither subsumes nor weakens. That second control replaces the argument nautilus#117's body made: the body cited a constant `ddf = -2.0` at `x0 = 5.0` returning NaN as proof that a finite negative curvature is rejected correctly, but that call never reaches the curvature check at all -- the Newton map is `x -> 2x - 3`, which diverges, and `2^100` is still finite in f32, so the NaN came from `lte(iters, 0)` after the budget ran out. Raising the budget to 1000 returns `inf`. Reaching the sign test requires starting *at* a stationary point of a concave function, which is what the new control does. One defect in the same function is deliberately not fixed here and is tracked separately: a non-finite **iterate** is still returned as a minimum through the same `eq(x_next, x)` early return, so that same constant `ddf = -2.0` at `max_iters = 1000` returns `inf` and an infinite first derivative with a correct constant `ddf = 2.0` returns `-inf`. That is a different quantity from the curvature, it wants its own decision between NaN and a runaway bound like `opt_gd_rec`'s `|x| > 1e15`, and widening this change to cover it would be new scope. `newton_minimize_1d` is `alpha` in `dist/stability.json`, so no stability freeze applies, and its signature is unchanged. Addresses nautilus#117.
