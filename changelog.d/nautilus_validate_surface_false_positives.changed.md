`scripts/validate_surface.py`'s README check no longer fails on the committed README. Its name extractor read every backticked lowercase token in a surface-table cell as an export claim, so `Nautilus.Optimize`'s stability label `(`alpha`)` and `Nautilus.Signal`'s "names ending in `_stub`" were reported as exports the modules lack -- two failures on unmodified `main`, with the README correct in both cases and the script wrong. The existing remedy for the same over-match was a hand-maintained skip set of method-suffix shorthand (`pdf`, `cdf`, `inv_cdf`, `sample`), which does not generalise, so the extractor now excludes two structural spellings instead: a parenthesised token, which annotates a row rather than listing a name, and a leading-underscore token, which states a naming pattern. Both exclusions rest on a property of the live surface rather than on a vocabulary of words to ignore -- matching label text would have been wrong, because `beta` is a label word and also a real `Nautilus.Special` export -- and `scripts/test_validate_surface.py` pins each property, so an export named `_private` or a parenthesised backticked export name in the README table fails a test rather than being skipped in silence. The check still reads ordinary backticked names as claims, which is pinned too, and the drop set being exactly these two tokens is measured rather than pinned -- the tests guarantee that no export name is excluded, not that nothing else ever will be. One effect is worth naming: `RealReadmeTest` calls `check_readme` and `ci.yml` runs `unittest discover -s scripts`, so README surface drift now fails CI for the first time, where the same drift passed before. Separately, `docs/releases.md` no longer names the newest published package in prose: it asserted that v0.7.46 was the last published release after v0.7.47 had shipped, so it now points at `gh release list` and at the tagged `reef.toml` instead of carrying a version that nothing updates.
