`Nautilus.Distributions.gamma_inv_cdf` returned a value from the wrong tail in two unrelated-looking regions, and both came from one pair of structures: each Newton step divided by the density floored at an **absolute** 1e-30, and a step that landed at or below zero was recovered by halving `x` once per iteration. Below `q = 1e-4` for a shape in roughly [1.9, 2.6] Wilson-Hilferty's `s` goes negative, so the start itself was floored to 1e-30; the density there is about 1.8e-8, so the first step was `q/pdf ~ 5e24` and landed about 27 decades above the root, and 75 to 79 of the 80 steps went on halving back — leaving the answer a function of the step count rather than of `q`. `gamma_inv_cdf(1e-5, 2, 1)` returned **8.271806** against a true 0.0044788163; `gamma_cdf(8.271806, 2, 1)` is 0.9976, so that is the 99.8th percentile where the 0.001st was asked for, and nothing about 8.27 looks wrong to a caller. The halving signature is visible in the returns themselves: 8.271806, 16.543612 and 24.815418 at neighbouring parameters are 1, 2 and 3 times the same number, and two different parameter pairs both returned exactly 1.6543612. `chi_squared_inv_cdf(1e-5, 4)` is the same point through `df/2`. The second region reached the same floor from the other side: a Gamma density is about `1/(scale*sqrt(2*pi*shape))`, so past a large enough `scale` the true density falls under an absolute floor and each step then removes only the fraction `pdf/floor` of the error — `gamma_inv_cdf(0.5, 2, 1e31)` was 3.0e-4 relative, 152x the documented bound, **at the median**, where the closed-form start is perfectly good and nothing is degenerate. The arithmetic closes: at shape 2 and scale 1e31 the true density is 3.12e-32, so `pdf/floor` is 1/32 and `0.9688^80 = 0.079` of the start's own 3.96e-3 error survives, predicting 3.1e-4 against the measured 3.0e-4. Four changes, none of which enlarges a budget — and the attribution between them is weaker than it looks, which is stated here rather than discovered later. Three of them are **independently sufficient** repairs of the lower-tail region: the maintained bracket, the asymptotic start, and the `ln P` residual. Removing any one alone changes no measured value, and removing any two alone changes no measured value; only removing all three reconstructs the original failure, at which point 5 of the 6 tests added here fail. That was established by mutation against the 194-test file and then again against a 550-case off-grid accuracy grid, where all three single mutants are **bit-identical** to the shipped lane. So the redundancy is a property of the algorithm rather than an artefact of thin coverage, and nothing in this repository, at any grid density affordable here, distinguishes the shipped solve from any single-structure-removed variant. The `scale` standardisation is the only singly load-bearing change, and it is load-bearing for the *other* region. **`scale` is divided out before the solve, and the dilation identity it rests on holds only where the unit root is a normal f32.** Over 275 probed triples, `gamma_inv_cdf(q, k, s)` and a caller's own `s * gamma_inv_cdf(q, k, 1)` agree bit-for-bit in 220 and within one f32 ulp in 40; in 6 they differ by 100%, because the f32 *unit* value is subnormal or zero while the direct call is correct — `(1e-4, 0.0706, 1e30)`, `1e35` and `1e38`, and `(1e-38, 0.5, 1e35)` and `1e38`, alongside the `1e20` row below. Those six vindicate the design rather than qualifying it, but the condition is the honest statement of the identity and one instance of it is not. `scale` is a pure dilation of this family — the CDF is `P(shape, x/scale)` — so solving on the unit-scale distribution and dilating at the end is exact, and no constant inside the loop now has a magnitude a `scale` can move. The dilation happens in f64 and is cast **once**: casting `exp(u)` to f32 first and multiplying in f32 loses a unit root below f32's smallest normal that the scale would have brought back, which returned exactly `0` for `gamma_inv_cdf(1e-4, 0.0706, 1e20)` whose true value is 1.3076351e-37. That bug was written during this change and caught by the row review round 3 of nautilus#152 had added for a different reason. **The start is the small-`q` asymptotic wherever Wilson-Hilferty's cube is non-positive.** `P(a, y) ~ y^a / Gamma(a+1)` as `y -> 0` is the leading term of the same series the CDF sums, so inverting it is accurate exactly where the closed form degenerates, and its logarithm is exact in the solve's own variable — `u = (ln q + lgamma(a+1))/a` — so it needs no `exp` and cannot underflow on the way in. AS 91 and Numerical Recipes both switch here. No threshold is introduced: the two branches are separated by the sign of `s`, and Wilson-Hilferty is not a start at all where `s <= 0`. **The solve maintains a straddling bracket and bisects whenever a Newton candidate leaves it.** The old loop had no bracket; its only guard was `x_next <= 0 -> x/2`, which is a descent and not a safeguard. Leaving the root's basin is now impossible, and an exhausted budget returns a point inside an interval that contains the root rather than wherever a descent had reached. The bracket is widened from the start by a **doubling** step, which makes its cap a guarantee rather than a hope: twelve steps span 4095 nats while the clamped start sits inside a window 1454 nats wide, and the low end always terminates because `P` is 0 once `exp(u)` underflows while `q` is strictly positive. **The variable is `u = ln y` and the residual is taken on `ln P`.** `dP/du` is `y*pdf(y)`, which is exactly the `gammainc_front` this module already has, so the quotient that needed a density floor is never formed. `P` is near-exponential in `u` in the deep lower tail, where Newton on `P` creeps — 53 of the 80 steps at `q = 1e-38, shape = 100` — while on `ln P` the same region is near-linear because `d(ln P)/du` is `a - y` to leading order; the 53-steps-to-13 comparison that motivated this choice was measured in a Python prototype of the algorithm over 2875 triples, **not in this lane**, and is quoted here only as the reason the residual is taken on `ln P`. **`gamma_inv_floor()` is deleted rather than split.** nautilus#162 recommended splitting it, on the grounds that it did two unrelated jobs — flooring `s^3` to keep a start positive and flooring the density to keep a division finite — which want different magnitudes. With a maintained bracket neither job exists: an unusable derivative means take the bisection step, and a degenerate closed form means take the asymptotic start. This is a deliberate departure from the issue's own proposal, not an oversight. **The 80-step budget is unchanged, and that is the result rather than an omission.** nautilus#162 established that raising it from 80 to 4000 returns the correctly rounded answer at both witnesses, and concluded the budget was the binding constraint; what the budget actually bounded was the length of a recovery the start and the missing safeguard made necessary. With those removed, the step counts measured in THIS lane by instrumenting the loop counter are: at most **4** over the accuracy gate's own quantile grid (118 arguments), up to **35** outside it at a small shape in a deep tail (`gamma_inv_cdf(1e-7, 0.0032, 1)` is the worst over 252 arguments), and never closer to the budget than **36 of 80**. The deep rows are bisections and not error — every one of those returns is correct — because a clamped start leaves a bracket about one nat wide and the loop halves it down to the 1e-10 tolerance. **Measured** against the accuracy gate's own mpmath oracle, evaluated at the f32 of every argument rather than at the decimal — the difference is a 5.5e-4 relative artefact at `q = 0.999999, shape = 10`, which belongs entirely to the harness: 109 measurable rows spanning `q` from 1e-38 to 0.999999, shape 0.0706 to 1e7 and scale 1e-20 to 1e30, **worst 5.3e-8**, about one f32 ulp. That is a grid worst over a continuum and therefore a lower bound on the true worst — a red-team sweep between the grid's points reached 5.63e-8, 6% higher, which is what a lower bound predicts. No **accuracy claim** in the book or in `SKILL.md` quotes it and no maximum is located; the figure appears only in this fragment and in the gate's own stdout. All eleven of nautilus#162's witnesses are now correctly rounded, and so is `gamma_inv_cdf(1e-4, 0.0706, 1e20)`, review round 3 of nautilus#152's own small-shape witness. No before/after ratio is quoted for that row: the witness was recorded at shape 0.07062688 and abbreviated to 0.0706 in the documents, which is a **different f32** and therefore a different call, and the figures in circulation for it (41.5x and 44.7x) differ by both the shape and whether the quantity is a ratio or a relative error. A figure that needs two conventions stated to be unambiguous is better left out than published. `parity/check_gamma_accuracy.py` drops its quantile `q` floor from 1e-4 to 1e-7, gains 1e30 in its quantile scale set (the thin set trades 1e20 for it rather than adding, so the top two shapes cost the same), adds 0.0706 and 2.1 to the shapes where the asymptotic start is taken, walks the whole 1e-7 to 1e-4 band at each of those shapes rather than one point each, and adds named rows for the exact non-monotone pair the region was patchy across — shape 2.1 was 2.7e+03 relative at `q = 1e-5` and correct to 2.8e-10 at `3e-5`, which a decade-stepped axis can straddle without landing on. The enforced case count goes from 1626 to **1847**, and the published claim in `docs/book/src/appendix/precision.md` moves with it. The `q` floor is now a probing choice rather than a bound: below about 1e-20 at a small shape the quantile itself falls under f32's smallest normal and the reference is excluded, so a deeper row would measure f32's quantisation rather than this implementation. Six tests are added and each carries the old wrong value as its own assertion, because a relative-error test alone passes a return that is merely closer. **One needs no reference value at all**, and it is the one worth keeping: a quantile is non-decreasing in `q` by definition, and the old lane returned 8.271806, 24.815418 and 0.014209238 at `q` of 1e-5, 3e-5 and 1e-4 — up by 3x, then down by three decades. That test is the one worth keeping because it needs no oracle, but its mechanism is **not** the bracket: the no-bracket mutant passes it. Monotonicity follows from Newton converging at all, which it does from either start. Twelve mutations were run, each asserting its anchor matched exactly once so that a no-op mutation is a hard error rather than a survivor. Four are singly detected: `scale` not divided out (10 tests), the premature f32 cast (1), **removing the pre-membership convergence test (6)** — which this fragment earlier predicted would be cost-only and is not — and starving the bracket widening to one step (2). Three survive singly, and are the three independently sufficient repairs above. **No test is added to kill them, and the reason is categorical rather than a preference.** The bracket underwrites a universally quantified claim — that the basin cannot be left, that an exhausted budget still returns a point inside a straddling interval — and no finite grid can check a universal, so its surviving mutation is expected and is not evidence against it. The asymptotic start and the `ln P` residual underwrite claims about typical cost, which a grid *can* check, and the measurement says they are cost-only. The bracket is therefore justified by argument rather than by measurement, and nothing in this repository would notice its removal. **A degenerate input changes behaviour.** `gamma_inv_cdf(0.5, NaN, 1.0)` aborted the process before this change with `numeric trap: domain in cast_trunc at i64`, measured identically on `0be29bb` and on nautilus#152's head, so it is pre-existing and neither change introduced it. It returns `NaN` now, because the asymptotic start takes `log_gamma(shape + 1)`, which traps on a NaN rather than propagating it — so the domain conditions are stated at the entry instead of being left to whichever arithmetic a NaN happens to reach first. That also makes a zero `scale` return `NaN` by a guard rather than by accident: with `scale` divided out it would otherwise have multiplied a finite unit quantile and returned 0. **A red-team round then found that the first version of that guard tested positivity and not finiteness, so an infinite shape passed it and `gamma_inv_cdf(0.5, +inf, 1)` returned `0.0`** — `1/(9*inf)` is 0, so the start clamps to the top of the window, `P(inf, y)` is not a usable probability, both widenings run to their caps and the bisection settles at `exp(-3386)`. A plausible-looking lower-tail number returned for a median is the exact failure class this change exists to remove, so re-introducing it at a degenerate input would have been a poor trade. All four non-finite parameter cases now return `NaN`, which is what the pre-#162 lane returned for them. The limits they arguably have — `+inf` for an infinite shape at any interior `q` — are deliberately **not** claimed: that is a semantic decision about a degenerate input, and this restores the previous answer rather than inventing a new one. The abort is one instance of a `cast_trunc`-on-a-shape-argument family that also covers `student_t_cdf(t, NaN)` and five exports named in nautilus#150; this change does not claim that family. The CDF's own separate defect is untouched and still documented as known wrong: `gamma_cdf`'s parameter guards read the **f32** quotient `x / scale`, so `gamma_cdf(1e-30, 0.25, 1e20)` returns exactly 0.0 against a true 3.49e-13 while the same call at `scale = 1` is correct. `gamma_inv_cdf` does not reach it — the solve calls `gammainc_p` in f64 directly — so the quantile is no longer the weaker of the two.
