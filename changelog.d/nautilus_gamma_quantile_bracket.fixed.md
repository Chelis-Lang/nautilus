`Nautilus.Distributions.gamma_inv_cdf` returned a value from the wrong tail in two regions, and both came from one pair of structures: each Newton step divided by the density floored at an **absolute** 1e-30, and a step landing at or below zero was recovered by halving `x` once per iteration. Below `q = 1e-4` for a shape in roughly [1.9, 2.6] Wilson-Hilferty's `s` goes negative, so the start itself was floored; the density there is about 1.8e-8, so the first step was `q/pdf ~ 5e24` and landed about 27 decades above the root, and the budget went on halving back — leaving the answer a function of the step count rather than of `q`. `gamma_inv_cdf(1e-5, 2, 1)` returned **8.271806** against a true 0.0044788163; `gamma_cdf(8.271806, 2, 1)` is 0.9976, so that is the 99.8th percentile where the 0.001st was asked for, and nothing about 8.27 looks wrong to a caller. The halving signature was in the returns themselves: 8.271806, 16.543612 and 24.815418 at neighbouring parameters were 1, 2 and 3 times one number, and two different parameter pairs both returned exactly 1.6543612. `chi_squared_inv_cdf(1e-5, 4)` is the same point through `df/2`. The second region reached the same floor from the other side: a Gamma density is about `1/(scale*sqrt(2*pi*shape))`, so past a large enough `scale` the true density falls under an absolute floor and each step removes only the fraction `pdf/floor` of the error — `gamma_inv_cdf(0.5, 2, 1e31)` was 3.0e-4 relative **at the median**, where the closed-form start is perfectly good. **A third region, which the issue's title does not name, is repaired with them**: deep `q` at a *large* shape, where `gamma_inv_cdf(1e-20, 1e7, 1)` returned 2502443800 against a true 9970738 and `(1e-10, 1e7, 1)` returned 5820766000 against 9979897. Its root cause is in another export — `normal_inv_cdf` returns NaN for every `q` at or below 1e-8, so the `z` Wilson-Hilferty is handed is NaN, `s` is NaN, the cube fails its positivity test and the floored start follows. That defect is not repaired here; it is `nautilus#166`, and `lognormal_inv_cdf` inherits it. This solve is robust to it by construction rather than by luck: a NaN `s` fails `gt(s, 0)` and routes to the asymptotic start, which does not read `z` at all. Four changes, none of which enlarges a budget. **`scale` is divided out before the solve.** It is a pure dilation of this family — the CDF is `P(shape, x/scale)` — so solving on the unit-scale distribution and dilating at the end is exact, and no constant inside the loop has a magnitude a `scale` can move. The dilation happens in f64 and is cast **once**: casting `exp(u)` to f32 first and multiplying in f32 loses a unit root below f32's smallest normal that the scale would have brought back, which returned exactly `0` for `gamma_inv_cdf(1e-4, 0.0706, 1e20)` whose true value is 1.3076351e-37. That bug was written during this change and caught by a row an earlier review round had added for a different reason. **The start is the small-`q` asymptotic wherever Wilson-Hilferty's cube is non-positive.** `P(a, y) ~ y^a / Gamma(a+1)` as `y -> 0` is the leading term of the same series the CDF sums, so inverting it is accurate exactly where the closed form degenerates, and its logarithm is exact in the solve's own variable — `u = (ln q + lgamma(a+1))/a` — so it needs no `exp` and cannot underflow on the way in. AS 91 and Numerical Recipes both switch here. No threshold is introduced: the branches are separated by the sign of `s`, and Wilson-Hilferty is not a start at all where `s <= 0`. **The solve maintains a straddling bracket and bisects whenever a Newton candidate leaves it.** The old loop had no bracket; its only guard was `x_next <= 0 -> x/2`, a descent rather than a safeguard. Leaving the root's basin is now impossible, and an exhausted budget returns a point inside an interval containing the root. The bracket is widened from the start by a **doubling** step, which makes its cap a guarantee rather than a hope: twelve steps span 4095 nats while the clamped start sits inside a window 1454 nats wide, and the low end always terminates because `P` is 0 once `exp(u)` underflows while `q` is strictly positive. **The variable is `u = ln y` and the residual is taken on `ln P`.** `dP/du` is `y*pdf(y)`, exactly the `gammainc_front` this module already has, so the quotient that needed a density floor is never formed; and `P` is near-exponential in `u` in the deep lower tail, where Newton on `P` creeps while on `ln P` the same region is near-linear. **`gamma_inv_floor()` is deleted rather than split.** The issue recommended splitting it, on the grounds that it did two unrelated jobs — flooring `s^3` to keep a start positive and flooring the density to keep a division finite. With a maintained bracket neither job exists: an unusable derivative means take the bisection step, and a degenerate closed form means take the asymptotic start. This is a deliberate departure from the issue's own proposal. **The 80-step budget is unchanged, and that is the result rather than an omission.** The issue established that raising it from 80 to 4000 returns the correctly rounded answer at both of its witnesses and concluded the budget was the binding constraint; what the budget actually bounded was the length of a recovery that a degenerate start and a missing safeguard made necessary. **No typical or maximum step count is published, and the omission is a result rather than an oversight.** Three figures were stated and falsified in consecutive review rounds: a prototype's 13; then "at most 4 on the accuracy gate's own quantile grid, 35 anywhere, never within 44 steps of the budget"; then the grid maximum turning out to be 5 and a wider sweep reaching 80 of 80 at `q = 9e-25, shape = 0.075`. Each was correct over the set that produced it and wrong as written, because the cost of this loop is governed by how far a clamped start sits from the root and no finite sweep bounds that. The claim FORM was the defect rather than the arithmetic, so the form is gone rather than renumbered. What holds without a sweep: the loop exits on convergence, on a bracket narrower than its tolerance, or on the budget, and on whichever exit it takes the value returned lies inside a bracket straddling the root. A deep-tail argument at a small shape spends its steps bisecting a one-nat bracket rather than diverging, and every such return measured is correct — including the ones that reach the full budget. **Measured** against the accuracy gate's own mpmath oracle, evaluated at the f32 of every argument rather than at the decimal — the difference is a 5.5e-4 relative artefact at `q = 0.999999, shape = 10` which belongs entirely to the harness — and with the returned value recovered as `f32(float(printed))` rather than `float(printed)`, which otherwise inflates a reported figure by up to 1.97x: **worst 5.3e-8** over the witnesses and the repaired regions, about one f32 ulp. That is a grid worst over a continuum and therefore a lower bound on the true worst; three independent review sweeps on three different grids reached 5.394e-8, 5.627e-8 and 5.685e-8, each slightly above it, which is what a lower bound predicts. None found a case over 2e-6. **Every asserted value was re-measured on this base.** An earlier revision of this change was built against Chelis 0.19.1 and a `gammainc_p` that `#175` has since rewritten with an asymptotic window for `shape >= 1e5`; all 24 values reproduce bit-identically under 0.19.4 on the new lane, including the four rows at shape 1e7 whose solve now touches that window -- and it is touched at a bracket endpoint rather than at the root: the first widening step lands about 80 from the shape where the window's half-width is 15811, while every converged root sits 1.3x to 2.6x outside it. The fifth deep row is at shape 1e3 and cannot enter the window at all, since it requires a shape of at least 1e5. So the values are a property of the quantile rather than of the series beneath it. `parity/check_gamma_accuracy.py` drops its quantile `q` floor from 1e-4 to 1e-7, gains 1e30 in its quantile scale set (the thin set trades 1e20 for it rather than adding, so the top two shapes cost the same), adds 0.0706 and 2.1 to the shapes where the asymptotic start is taken, walks the whole 1e-7 to 1e-4 band at each of those shapes rather than one point each, and adds named rows for the exact non-monotone pair the region was patchy across — shape 2.1 was 2.7e+03 relative at `q = 1e-5` and correct to 2.8e-10 at `3e-5`, which a decade-stepped axis can straddle without landing on. The count the accuracy **gate enforces** goes from 1655 to **1876 measured cases** of 1923 generated, re-derived from the merged `cases()` on this base rather than carried forward or added: this change and nautilus#165 both added rungs, and only the merged grid knows the total. The naive sum happened to be right here because the two sets of rungs do not overlap, which is luck rather than method. The `q` floor is now a probing choice rather than a bound: below about 1e-20 at a small shape the quantile itself falls under f32's smallest normal and the reference is excluded, so a deeper row would measure f32's quantisation. Seven tests are added and each carries the old wrong value as its own assertion, because a relative-error test alone passes a return that is merely closer. One needs no oracle at all — a quantile is non-decreasing in `q`, and the old lane went 8.271806, then 24.815418, then 0.014209238 across `q` of 1e-5, 3e-5 and 1e-4 — though its mechanism is **not** the bracket, since the no-bracket mutant passes it. Each of the three redundant structures (bracket, asymptotic start, `ln P` residual) is **inert alone**, reproduced over the test file and over off-grid accuracy grids by two independent reviewers; **every pair is detected**, which `test_gamma_inv_cdf_needs_its_bracket_at_a_large_shape_in_a_deep_tail` is what buys — at `gamma_inv_cdf(1e-38, 1e7, 1)` the bracket-plus-start pair returns exactly `0.0` against a correctly rounded 9959065; and all three together fire seven tests. **A degenerate input changes behaviour.** `gamma_inv_cdf(0.5, NaN, 1.0)` aborted the process before this change with `numeric trap: domain in cast_trunc at i64`, measured identically on two earlier bases, so it is pre-existing. All four non-finite parameter cases return `NaN` now. For `+inf` shape that restores the previous answer, which is the warrant for choosing NaN over the limit; it is **not** true of all four, since a `-inf` shape and a NaN shape both aborted, so for those two this is a new answer and an abort is not a NaN return. An infinite shape passes a positivity test, and without the finiteness leg `gamma_inv_cdf(0.5, +inf, 1)` returned `0.0` — a plausible-looking lower-tail number for a median, the exact failure class this change exists to remove. The limits a non-finite parameter arguably has are deliberately not claimed. Part of nautilus#162.
