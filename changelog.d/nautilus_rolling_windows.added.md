Add `Nautilus.Rolling`: f64 rolling and expanding `sum`, `mean`, `var`, `std`, `min` and `max` over `List[f64]`, plus `shift`, `shift_fill`, `shift_clamped`, `diff` and `pct_change`, each with a `tensor_` entry point taking `&tensor[n, f64]`. Warm-up and `min_periods` match pandas for finite, NaN-free input, checked against committed pandas goldens by `scripts/check_rolling_parity.py`. A window whose observation count is not above `ddof` is `Some(NaN)`, as in pandas. A non-finite input value is a value here and propagates through every reduction, where pandas treats NaN as missing; the book records that divergence. The lag family is defined except for the `len(xs)` most negative values of `k`, which overflow the index arithmetic. Two module-local departures from the rest of the package, both argued in `spec/scope.md` and the book: the module is concrete f64 rather than `[prec: Float]`, and a position with no value is `None` rather than a NaN sentinel, so a warm-up cannot be dropped by a caller that only wanted the numbers. `scripts/check_rolling_c_lane.py` is the repository's only `chelis build` gate, and it checks both an in-package consumer and a separate package installed into a throwaway Reef store: `chelis reef build` does not enter host lowering, so two upstream C-lane limitations (`docs/UPSTREAM_BUGS.md`) were invisible to every other gate. Addresses nautilus#85.
